title: 'Stop rolling back a failed commit with truncate(2): the .jsonl logs are append-only'
---
## What
The user decided (2026-10-22) that every `.jsonl` file is append-only and goes through Extras `JSONLFile`: no code truncates, rewrites or replaces a log file, and a removal is an appended tombstone record (see ^4wft5zd).

`LogFileMark.restore()` (`Sources/FoundationModelsKanban/Events/LogFileMark.swift`) still puts a log file back after a failed commit with `truncate(2)` to its recorded size, and removes a file that the commit made. `Commit.rollBack(_:)` calls it when an append or the signature read fails (plan.md §5.4 step 5.5). That rewrites a `.jsonl` file outside `JSONLFile`, which the new rule forbids.

Found while moving EventLog onto JSONLFile (^4wft5zd); out of that card's scope.

## Decide
A rollback that only appends needs a design decision (for example: leave the partial lines and rely on the transaction `files` check at load, `IncompleteTransactions`, which already ignores a transaction that is not in every file it names; or append a compensating record). Ask the user before coding.
