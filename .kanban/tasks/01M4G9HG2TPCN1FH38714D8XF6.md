## What
The owner decided: undo of a transaction removes each node that the transaction made. This includes a node made as a side effect (an unknown tag in `addTask`, a new column in `moveTask`). The current rule in plan.md §6.5 ("no inverse: the node stays") is not wanted.

Now `Sources/FoundationModelsKanban/Undo/Inverse.swift:49-61` (`makesExplicitly`) decides from the `ops` names of the call. Thus the result depends on which other mutations are in the call.

Final rules:
- Undo keeps these nodes: the board node, the default columns that auto-init made, and the session actor that a call made automatically.
- Each other node that the transaction made gets the inverse `delete: true` on its first patch. Do not use the `ops` names for this decision.
- A tag that a `#marker` made live again with `delete: false` gets the inverse `delete: true`.
- The conflict rule stays: if a later transaction uses the node (for example a later task tags `bug`), undo gives `UNDO_CONFLICT` unless `force: true`.
- A later call by the session actor does not count as a later use of that actor for `UNDO_CONFLICT`.
- Undo of `moveTask` to a new column: the inverse first moves the task back, and then checks the delete of the column. Thus the undo does not give `COLUMN_NOT_EMPTY`.
- Update plan.md to match:
  - §6.5: the table row that starts "the first patch of a node that a mutation made as a side effect".
  - §11: the bullet that starts "Undo: for each public mutation", and the bullet that starts "Undo of `addTask` that made the tag `bug`".
