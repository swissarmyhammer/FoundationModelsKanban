## What

The filter agent accepts a statement only when it parses AND each name in it names a node of the board (divergence.md §17, "The loop"). Make one function that does the name check.

- Input: a parsed `FilterExpr` and the board state.
- Check each `#tag` (a tag slug or a virtual tag), each `@actor` (actor id or the slug of its name), each `$project`, and each column name, against the live board.
- Output: success, or an `INVALID_FILTER` error with the position of the name, a specific message ("no tag named `urgnt`"), and a corrected example (the nearest name, if there is one).
- First look at `S/Filter/TaskFilter.swift`, `S/GraphQL/TaskSelection.swift` and `FilterSyntaxError.kanbanError(in:)`. Use the existing name resolution and message style. Do not make a second resolver. The filter of `tasks(filter:)` does not change: a name that names nothing still gives an empty result there.

## Acceptance criteria

- [x] A statement with only known names passes.
- [x] An unknown tag, actor or project gives `INVALID_FILTER` with the position and a specific message.
- [x] The virtual tags of `VirtualTag.allCases` (for example `READY`, `BLOCKED`, `DONE`, `HIGH`) pass.
- [x] The message gives the nearest name when one is close.

Note: `BLOCKING` is removed by divergence.md Q1 and C1. It is not a virtual tag, and `#BLOCKING` is an ordinary tag filter.
