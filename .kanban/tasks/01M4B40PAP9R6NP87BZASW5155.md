## What
Prove that each error code that a public mutation or query can give comes back in the correct GraphQL form. The basis is plan.md §4.4. The `KanbanError` type and its messages come from the error catalog task.
- One `execute` test for each of these codes: `NOT_FOUND`, `AMBIGUOUS_ID`, `ACTOR_NOT_FOUND`, `DUPLICATE_ID`, `COLUMN_NOT_EMPTY`, `DEPENDENCY_CYCLE`, `TAG_RENAME_CYCLE`, `INVALID_FILTER`, `INVALID_TAG_NAME`, `INVALID_SLUG`, `INVALID_ORDINAL`.
- The codes `NOTHING_TO_UNDO` and `UNDO_CONFLICT` are tested in the undo task, `BOARD_BUSY` in the commit task, and `INVALID_VARIABLES` and `SUBSCRIPTION_NOT_IN_TOOL` in the tool task.
- A failed field gives `data` for the other fields of the call and one item in `errors`. The tool does not throw for a GraphQL error.

## Acceptance Criteria
- [ ] Each of the 11 codes above comes back with `message`, `path`, and `extensions.code`, and the message equals the expected text from `KanbanErrorTests`.
- [ ] A document with two mutation fields, where the second fails, writes the patches of the first and returns its data.
- [ ] No GraphQL error makes `execute` throw.

## Tests
- [ ] `Tests/FoundationModelsKanbanTests/GraphQL/ErrorCoverageTests.swift`.
- [ ] Run `swift test --filter ErrorCoverageTests`; expect all pass.

## Workflow
- Use `/tdd` — write failing tests first, then implement to make them pass.
