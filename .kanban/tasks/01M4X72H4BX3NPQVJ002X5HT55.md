## What
divergence.md X7 (§1.1, §11 bugs). This is work on the Swift package (S/ = Sources/FoundationModelsKanban/).

Problem: `undeleteTask` can bring back a cycle. The cycle check runs only when `dependsOn` or the body changes (S/GraphQL/TaskMutations.swift:303-305, S/GraphQL/UndoMutations.swift:289-298). `undeleteTask` calls `setDeleted` (S/GraphQL/ColumnActorMutations.swift:443-453), which does no cycle check. Example: A→B→C, then delete B, then add C→A, then undelete B. The result is the cycle A→B→C→A, with no error. This can occur in one board or across boards.

Change: `undeleteTask`, and an undo (or redo) that makes a tombstoned task live again, run the same cycle check as a write of `dependsOn`. A cycle gives `DEPENDENCY_CYCLE` and writes nothing. For a cycle across boards, lock each board that the check read, as the current cross-board cycle check does.

## Acceptance Criteria
- [ ] The example above gives `DEPENDENCY_CYCLE` on `undeleteTask(B)`, and B stays deleted.
- [ ] Undo of the delete of B in the same state gives `DEPENDENCY_CYCLE` and writes nothing.
- [ ] The same example across two boards gives `DEPENDENCY_CYCLE`.
- [ ] `undeleteTask` with no cycle works as before.
