## What
Change the loose refs that an agent writes to stored refs. The basis is plan.md §3.2 (short forms, target board) and §4.4 (`AMBIGUOUS_ID`).
- `Sources/FoundationModelsKanban/Identity/RefResolver.swift`: resolve against a `Graph` and an expected node type. Accept a full URI, a full ULID, a 7-character short id, `^short`, a unique ULID prefix (case-insensitive), a slug, and a tag name (normalized to a slug, then the rename redirect).
- Canonical forms win over a colliding prefix. A prefix with many matches gives `AMBIGUOUS_ID`, and the message lists the matches as short ids.
- A full URI with the current key gives a local ref; a URI with a different key gives a remote ref (only valid where the caller accepts cross-board refs).
- An option to resolve to a tombstone (the undelete mutations need it).

## Acceptance Criteria
- [ ] Each short form resolves to the same task.
- [ ] An ambiguous prefix gives `AMBIGUOUS_ID` with the matching short ids.
- [ ] A ref to a node that does not exist gives `NOT_FOUND`.
