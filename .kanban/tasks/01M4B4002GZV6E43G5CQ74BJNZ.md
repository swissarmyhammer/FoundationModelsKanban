## What
Create and change tasks. The basis is plan.md §4.2, §5.5, §6.1, and §3.3 rule 6.
- `MutationResolvers.swift` (task part): `addTask(title!, body, column, ordinal, assignees, tags, dependsOn)` and `updateTask(id!, …)` (a list replaces the list as an `add`/`remove` difference; a missing field = no change; `null` = clear). There is no time input: `created`, `due`, or `scheduled` in the input is a validation error.
- Mint the task ULID with a unique short id. Default column = minimum `order`; default ordinal = append at the end (`Ordinal.after` the last). If `addTask` has no assignee, use the session actor if it was a known actor before the call. An unknown assignee gives `ACTOR_NOT_FOUND`.
- Tags: an unknown tag in `tags` or a new `#marker` in the body writes a tag `set` patch; a marker to a tombstoned tag writes `delete: false`.
- `dependsOn`: a same-board target is stored as a local ref, a different board as a full URI. A cycle from an edge or a body marker gives `DEPENDENCY_CYCLE`. `updateTask(dependsOn:)` that removes a target also removes its URL from the body (an `edit` patch).
- `body`: an `edit` patch with the diff; never the full text. `body: null` and `body: ""` write a diff to the empty text.

## Acceptance Criteria
- [ ] `addTask` returns the new task with `id`, `shortId`, `ready`, and `blockedBy`; each mutation with `body` writes one `edit` diff, and `body: null` empties the body.
- [ ] A dependency cycle is refused, and nothing of that field is written.
- [ ] Two processes add a task at the same time: both tasks are written, and the short ids are unique (the commit check runs again).
