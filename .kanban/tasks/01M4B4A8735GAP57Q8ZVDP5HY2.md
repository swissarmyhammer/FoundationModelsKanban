## What
One error type that all code uses from the start. The basis is plan.md §4.4.
- `Sources/FoundationModelsKanban/GraphQL/Errors.swift`: `KanbanError` with one case for each code: `INVALID_VARIABLES`, `NOT_FOUND`, `AMBIGUOUS_ID`, `ACTOR_NOT_FOUND`, `DUPLICATE_ID`, `COLUMN_NOT_EMPTY`, `DEPENDENCY_CYCLE`, `TAG_RENAME_CYCLE`, `NOTHING_TO_UNDO`, `UNDO_CONFLICT`, `INVALID_FILTER`, `INVALID_TAG_NAME`, `INVALID_SLUG`, `INVALID_ORDINAL`, `BOARD_BUSY`, `SUBSCRIPTION_NOT_IN_TOOL`. Each case carries the data that its message needs (for example the matching short ids for `AMBIGUOUS_ID`).
- `code` (the string above), `message` (a sentence with a correction), and a function that makes the GraphQL error JSON `{ message, path, extensions: { code } }`.
- No dependency on the GraphQL engine: the JSON is made with `Codable`.

## Acceptance Criteria
- [ ] Each case gives its exact code string.
- [ ] Each case gives the expected message text (one fixed expected string for each case in the test).
- [ ] The JSON form has `message`, `path`, and `extensions.code`.

## Tests
- [ ] `Tests/FoundationModelsKanbanTests/GraphQL/KanbanErrorTests.swift`: one test for each case with the exact expected message.
- [ ] Run `swift test --filter KanbanErrorTests`; expect all pass.

## Workflow
- Use `/tdd` — write failing tests first, then implement to make them pass.
