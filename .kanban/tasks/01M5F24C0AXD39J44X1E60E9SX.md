    ### implement — changed

    **Design**
    - One `ChangeFeed` per `BoardEngine` (`nonisolated let feed`). The feed owns the Extras `ChangeLog<LoggedChange>` (capacity from `HostConfiguration.changeLogCapacity`, default 1024). Every session view reads the same log and the same cursors.
    - `host.publish` asks each registered view to log the changes of its loaded engines that are not logged yet this round. Each round is computed and appended once. A loaded engine that no view can log gets `feed.restart()`: a new log epoch, and its subscribers end with `RESYNC_REQUIRED`.
    - Subscribers read the log through a `SubscriberRelay` into their own `bufferingOldest(capacity)` stream. A dropped event ends the stream with `RESYNC_REQUIRED`. A move to a new feed restarts the relay on the new log. Each relay task has a run number, and the check plus the yield happen under the lock, so a cancelled old task cannot deliver a stale event. This fixed a flaky failure in `ChangeFeedTests.movedSubscriberGetsEventsOfNewFeed`.
    - To bound memory, the feed keeps the board state of only the newest 16 rounds (`heldRoundCount`). A change from an older round resolves against the newest held round.
    - `cursor` / `cursor(board:)` / `Board.cursor` read the feed cursor under the serial gate. Related boards read the cursor and then the session, so a client may see a change again but never misses one.
    - `Change.cursor` / `added` / `changed` / `removed` (as `[ID!]!`) are added. `added` covers created and restored nodes, `changed` covers updated nodes, `removed` covers deleted nodes. All node types are included (board, column, task, tag, actor, comment).
    - On history `Change`s, `cursor` is the cursor of the board the query read.
    - Changes with no node updates are not appended.
    - `Subscription.changes(after:)` is added, with `kanbanChanges` as an alias.
    - The rule-9 exception is removed from `EndpointConventionTests`, and the golden SDL is re-recorded.

## What
KANBAN-7 (TestudoApp/features/packages/foundationmodels-kanban.md) under EXTRAS-9 rev 2 rule 9 and EXTRAS-10. Blocked on the EXTRAS-10 gate task (5pf8w1x).

- Each `Change` event (Sources/FoundationModelsKanban/Observe/Change.swift) has at least `cursor: String!` (opaque; it comes from ChangeLog), `at: DateTime!`, `added: [ID!]!`, `changed: [ID!]!` and `removed: [ID!]!`. One event can hold many items. Kanban keeps `txn`, `actor`, `origin` and the per-node updates (ops) as extra fields.
- One `ChangeLog` per board engine, made once per port/folder, not once per tool copy. Every change goes through it: own commits, watcher batches, and transactions from a `git pull` (today `since` compares ULIDs and can miss old ones).
- The root query `cursor: String!` gives the cursor of the state that a query reads (read under the serial gate with the board). The optional `cursor(board: String)` covers a related board; no argument means this folder's board. Keep `Board.cursor` too.
- `Subscription.changes(after: String, board: String, filter: String)` replays the buffered events after `after`, then the live events, in order, using `ChangeLog.changes(after:where:)` for the per-subscriber filter. A cursor that is too old, from another epoch (a restart), or after the newest event gives `RESYNC_REQUIRED`. With no `after`, the behavior is as today (live only).
- Alias: `kanbanChanges` → `changes`.
- Remove the rule-9 exception from the conformance test that task esc56vk adds.

- [ ] `{ cursor }` followed by `changes(after: cursor)` gives exactly the changes after the read, with none lost and none repeated, including watcher and pull changes
- [ ] Each event fills `added`, `changed` and `removed` with the ids of the task, column, tag and actor nodes it touched
- [ ] A cursor that has left the buffer, comes from before a restart, or is past the newest event gives `RESYNC_REQUIRED`
- [ ] `GraphQLEndpointConformance.problems` is empty with no rule-9 exception
