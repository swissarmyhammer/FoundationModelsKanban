## What
KANBAN-7 (TestudoApp/features/packages/foundationmodels-kanban.md) under EXTRAS-9 rev 2 rule 9 and EXTRAS-10. Blocked on the EXTRAS-10 gate task (5pf8w1x).

- Each `Change` event (Sources/FoundationModelsKanban/Observe/Change.swift) has at least `cursor: String!` (opaque; it comes from ChangeLog), `at: DateTime!`, `added: [ID!]!`, `changed: [ID!]!` and `removed: [ID!]!`. One event can hold many items. Kanban keeps `txn`, `actor`, `origin` and the per-node updates (ops) as extra fields.
- One `ChangeLog` per board engine, made once per port/folder, not once per tool copy. Every change goes through it: own commits, watcher batches, and transactions from a `git pull` (today `since` compares ULIDs and can miss old ones).
- The root query `cursor: String!` gives the cursor of the state that a query reads (read under the serial gate with the board). The optional `cursor(board: String)` covers a related board; no argument means this folder's board. Keep `Board.cursor` too.
- `Subscription.changes(after: String, board: String, filter: String)` replays the buffered events after `after`, then the live events, in order, using `ChangeLog.changes(after:where:)` for the per-subscriber filter. A cursor that is too old, from another epoch (a restart), or after the newest event gives `RESYNC_REQUIRED`. With no `after`, the behavior is as today (live only).
- Alias: `kanbanChanges` → `changes`.
- Remove the rule-9 exception from the conformance test that task esc56vk adds.

## Acceptance Criteria
- [ ] `{ cursor }` followed by `changes(after: cursor)` gives exactly the changes after the read, with none lost and none repeated, including watcher and pull changes
- [ ] Each event fills `added`, `changed` and `removed` with the ids of the task, column, tag and actor nodes it touched
- [ ] A cursor that has left the buffer, comes from before a restart, or is past the newest event gives `RESYNC_REQUIRED`
- [ ] `GraphQLEndpointConformance.problems` is empty with no rule-9 exception

## Tests
- [ ] Read + subscribe race: a commit between the query and the subscribe is delivered
- [ ] A watcher change (a file written outside the engine) and a multi-transaction batch like a git pull get cursors
- [ ] A buffer overflow and a cursor from a new epoch each give `RESYNC_REQUIRED`
- [ ] A filtered subscriber still sees the events in order
- [ ] The alias `kanbanChanges` works and shows in `extensions.rewrites`
